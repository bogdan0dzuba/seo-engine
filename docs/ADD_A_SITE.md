# Подключить второй сайт за час

Пример: sites/lida.

Нужны Python 3.10+, домен, список разделов и отдельный каталог данных. Для
первого офлайн-запуска подготовьте локальную копию HTML и sitemap. Никаких
дополнительных пакетов Python нет. Агент выполняет команды из корня checkout;
человек заменяет mysite, example.org, даты и пути своими значениями.

## 0–10 минут: отдельный конфиг

```sh
unset SEO_ENGINE_DATA
python3 -m engine.cli init-site --site mysite --domain https://example.org --data-dir /absolute/path/seo-data/mysite
```

Откройте sites/mysite/site.yaml. Это JSON без комментариев. Обязательны только
три поля, которые уже созданы: domain, sections, data_dir. Поправьте sections;
для статей вне /blog/ задайте article_section. Все поля и значения по умолчанию
описаны в [FIELDS.md](../sites/_template/FIELDS.md).

## 10–25 минут: доступные источники

Для обхода добавьте site_files (абсолютный путь к копии HTML) и sitemap
(например sitemap.xml). Движок читает диск, сетевой обход сайта не выполняет.
Без site_files стадия crawl пропускается. sitemap может ссылаться на дочерние
карты, все URL должны принадлежать настроенному домену.

Для аналитики нужны доступы в GSC, Яндекс Вебмастер и Метрику, но можно начать
с любого одного источника. В GSC выдайте сервисному аккаунту право чтения и
укажите gsc_property. У Яндекса укажите webmaster_host_id и/или metrika_counter.
OAuth должен иметь права чтения соответствующего сервиса. Доступ Метрики не
зависит от наличия Вебмастера. Если доступа нет, соответствующее поле и запись
ключа не добавляйте: источник отключён и не вызывает ошибку.

Владелец сохраняет ключи в macOS Keychain; в конфиге только ссылки на них:

```json
"keychain": {
  "google": {"account": "mysite", "service": "MYSITE_GSC_KEY"},
  "yandex": {"account": "mysite", "service": "MYSITE_YANDEX_TOKEN"}
}
```

Это фрагмент объекта site.yaml, а не отдельный файл. Google item содержит JSON
service account либо его hex; Yandex item — OAuth token. Не кладите секреты в
репозиторий, команды или отчёты. Живой GSC требует системные security и openssl
на macOS; офлайн-конвейер работает и на других ОС.

Для роботов укажите access_log (локальный JSON access log) и доверенный
client_address_header. Добавьте внутренние проверки в internal_user_agents,
свои маркеры запросов в internal_query_markers. Формат и приватность — в
[контрактах](contracts.md). Wordstat подключается необязательным списком
wordstat_files со сохранёнными JSON. Это не живой API Wordstat.

Для полностью офлайн-проверки задайте snapshot_dir: подпапки YYYY-MM-DD с
сырыми JSON ответов, например gsc_page.json с _window, rows и keys. Или положите
фикстуры прямо в data_dir/raw/YYYY-MM-DD. Пример полного сценария —
[test_round3.py](../tests/test_round3.py), test_init_to_card_offline_fixtures.
Офлайн-данные можно загрузить без Keychain и без API-доступов.

## 25–45 минут: пройти конвейер

```sh
python3 -m engine.cli collect --site mysite --date 2026-11-12
python3 -m engine.cli crawl --site mysite --date 2026-11-12
python3 -m engine.cli load --site mysite --date 2026-11-12
python3 -m engine.cli signals --site mysite --date 2026-11-12
python3 -m engine.cli propose --site mysite --date 2026-11-12
python3 -m engine.cli card --site mysite --date 2026-11-12
python3 -m engine.cli report --site mysite --date 2026-11-12
```

Для чтения живых API повторите collect с явным --live и затем остальные стадии.
Для истории добавьте --backfill; диапазон API можно указать --start и --end.
collect без --live работает только с файлами. Код 1 у живого collect означает
ошибку сбора; код 2 у signals — STALE. Не игнорируйте их: прочитайте диагностику,
но report, propose и card можно выполнить отдельно для просмотра имеющихся
данных. Отсутствие данных не превращается в нулевые показатели.

## 45–55 минут: прочитать результат

Откройте data_dir/reports/ПОНЕДЕЛЬНИК.html или .txt: в начале сводка и свежесть,
затем источники, окна, сигналы и ограничения. Два окна GSC не складываются;
наблюдаемый спрос не означает рост. Проверьте дату реального измерения, а не
только дату запуска. STALE означает, что свежесть не подтверждена.

data_dir/proposals/ДАТА.json содержит все черновики с исходными сигналами,
риском, формулой очков и заготовкой опыта. data_dir/cards/ПОНЕДЕЛЬНИК.txt — одна
карточка недели: что, почему, что будет и как откатить. Повторные запуски недели
сохраняют первый выбор low/medium; если страница занята опытом, он отзывается
без выбора замены. High выводится отдельно под «Нужно согласие». Ни карточка,
ни предложение ничего не публикуют и не запускают опыт.

Страницы моложе 28 дней на конец измеренного окна и с неизвестным возрастом
исключаются. Для объединения проверяются все участвующие страницы. Новая статья
предлагается по спросу на зрелую опорную страницу; текст и новый URL не выдумываются.
Потенциал и уверенность — фиксированные эвристики приоритета, не прогноз эффекта.
Кандидат контроля выбирается в том же разделе, с близкими показами и позицией;
это редакционный кандидат, пригодность нужно подтвердить перед запуском.
До принятия решения все предложения — черновики: наличие другого предложения
на контрольной странице не означает её правку. Контроль оставляют без изменений.

При запуске опыта внесите запись в effects_file: id, date, status=running,
record — JSON-строка с treatment_pages и control_pages (списки путей). Можно
импортировать прежние текстовые записи с URL. Активные и unassessed записи
резервируют и опыт, и контроль. Статусы completed/closed/cancelled/canceled/
rejected/draft/planned/finished/inactive не резервируют страницы. Будущие записи
не используются. Для legacy-текста извлекаются явно перечисленные URL/пути;
описания вида «и ещё 15 дочерних страниц» нужно заменить точным списком.
После изменения файла снова выполните load и propose. Без сопоставимого
контроля или достаточного окна вывод об эффекте откладывается. Перед реальной
правкой сохраните исходники: движок не делает резервную копию сайта.

## 55–60 минут: ночной запуск

Когда ручной проход проверен и разрешена установка локальной ночной задачи:

```sh
ops/install-nightly.sh install mysite 5 40
```

На macOS это устанавливает launchd только для выбранного сайта. Время локальное.
Ночная команда читает API (--live), затем выполняет crawl, load, signals, report,
propose и card. Логи: data_dir/nightly.stdout.log и nightly.stderr.log. Для
ручного прохода того же сценария: `python3 -m engine.nightly --site mysite --live`.
Снять расписание: `ops/install-nightly.sh remove mysite`. Само чтение этого
руководства и init-site ничего в launchd не устанавливают. На других ОС
используйте свой планировщик с тем же рабочим каталогом и отдельным data_dir.
