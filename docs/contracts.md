# Контракты данных и границы интерпретации

## Store

Один конфиг → один data_dir → один SQLite. `SEO_ENGINE_DATA` — точный каталог
сайта, не общий родитель. Никакого автоматического поиска ключей или адресов.
Схема создаётся идемпотентно. UPSERT сохраняет rowid, использованный в signals.
Raw-файлы сохраняются атомарно. Backfill копирует JSON со snapshot_dir, начиная
с backfill_start; существующие raw не перезаписывает. Для исторического `--date`
load/signals не используют снимки после этой даты. Crawl читает текущие файлы:
его дата — дата обследования, а не реконструкция старого состояния сайта.

`page_day`/`query_day`: `grain=day` для истинных дат, `grain=window` для
агрегатов. Первичный ключ содержит источник, обе границы и измерения.
Скользящие окна GSC/Метрики нельзя складывать. Старый GSC без _window
восстанавливается по контракту исходного сборщика: 28 дней, конец snapshot−3.
Новый GSC сохраняет явные границы и daily date×page×query, со всей пагинацией.
Запросы GSC анонимизированы и могут не суммироваться до общего числа показов.
Вебмастер: popular_complementary_indicator — популярный контрагент измерения,
а не полная связка query×page. Движок не создаёт из него вымышленные связи.

`metric_day` хранит Метрику с исходными названиями измерений, funnel, digest,
Wordstat, историю и диагностику Вебмастера. Окна и raw provenance сохранены.
`ai_visibility`: запросы HTTP из лога и визиты Метрики различаются по source;
их нельзя суммировать. `ai_panel` — схема и loader, никаких API моделей.
Положить `ai_panel.json` в raw/date как список записей со всеми полями схемы.
Поле raw_answer_path указывает уже существующий ответ, не вызывает модель.
`experiment` импортирует текст записей E-0001…E-0003 без причинного вывода;
proposal заполняется командой propose; decision/change_log/effect остаются пустыми до решений и измерений.
Статус unassessed означает «эффект не оценён», исходный ход опыта — в record.

## Freshness

Свежесть — не возраст файла и не дата запроса. Порог: >7 дней, неизвестная
или будущая дата → STALE. Нулевые history/value не считаются реальными данными.
Для Yandex использованы непустые in-search/indexing history и last_access_date
sitemap; queries history не доказательство. В отчёте показана каждая из трёх
опор и самая новая реальная дата, даже если свежий API вернул старую историю.
Если в последнем снимке отсутствует источник, берётся последнее известное
реальное наблюдение этого источника, без обновления его даты.
Wordstat использует конец измеренного месяца, и только непустые ненулевые
items; свежая ошибка 403 не оживляет старую статистику. Каждый файл отдельно.
Метрика: только ненулевой ряд с датой измерения; funnel: конец непустого окна
минус один день; digest: дата отчётного дня при наличии top_pages.

## Signals v1

Все сигналы содержат numbers и source_rows. Поиск — последнее полное доступное
окно GSC. Striking distance: позиции 8–20, показы >= striking_distance_min_impressions (20).
Low CTR: позиция <=10, CTR < low_ctr и >= low_ctr_min_impressions (50); пороги в конфиге.
No impressions: только статьи, возраст >=28 дней на КОНЕЦ окна; отсутствие
возвращённой строки не равно измеренному нулю (лимиты GSC). Когорты 28+,
14–27, 7–13, 0–6, after window, unknown показывают числа; доля вычисляется
только для 28+. Молодые статьи и страницы с неизвестной датой исключены.
Two pages one query: реальная GSC page×query, минимум две страницы с >= two_pages_min_impressions (10) каждая.
Cluster traction: наблюдаемые показы/клики по Wordstat cluster, иначе по разделу;
это спрос в окне, а не доказанный рост или причинный эффект.
Not in Yandex index: только явный отрицательный статус indexing sample
NOT_INDEXED / EXCLUDED / NOT_IN_SEARCH. Отсутствие в samples не доказательство.
Нынешние сохранённые материалы не дают полного списка отрицательных статусов;
правило может возвращать 0. История и summary при этом доступны для анализа.
AI demand: только search index/user-triggered fetch, кроме обычных поисковиков
и spoofed; >= ai_robot_min_hits (3), один сигнал на страницу; число запросов,
с отдельным verified_requests. Unverified demand — заявленный UA, не доверие.
Robot 404: сгруппированы по пути, >= robot_404_min_hits (3). Probe-пути
(.env, .git, wp-*, SQL/backup и подобные) вынесены в один probe_noise.
Tech issues: metadata, H1, canonical, JSON-LD, noindex, тонкий текст,
дубли, сироты, отсутствующие файлы и внутренние ссылки.
Agent trust: verified user-triggered fetch + локальные panel citations.
New bot: неизвестная bot/agent UA семья, >=2 дня наблюдений, последний
наблюдаемый день >=10 запросов и >1.5 среднего остальных наблюдаемых дней.
Период запросов роботов и panel — последние 7 календарных дней, UTC.

## Robots / privacy

Список классов в ai_bots.yaml — данные, не проверка подлинности. Обычные
поисковые боты отделены в non_ai_bots.json. IP-источники издателей перечислены
в ip_sources.json. Ближайший снимок выбирается в пределах ±30 дней; при
равном расстоянии предпочтение прошлому. Нет совпадения IP, нет заголовка
или нет близкого снимка → unverified. Нет опубликованного источника →
unavailable (также отмечено verification в снимке диапазонов). Семейства
проверяются раздельно. Запросы .env, .git, SQL/backup, wp-admin под известным
AI/бот именем → spoofed. Доверять X-Forwarded-For можно только если входящий
proxy перезаписывает его; эту предпосылку сервер должен обеспечивать сам.

Raw лог не копируется. Отпечаток строки SHA256 + номер одинакового вхождения
обеспечивают идемпотентность пересекающихся логов и сохраняют точные дубли.
В БД остаются дата, класс, статус, путь без query, assistant и provenance;
не IP, не исходный UA. Поля IP используются только в памяти. bot_day без expiry.
Особые пути отмечены special. malformed/excluded_internal/frozen_bytes в raw.
Нельзя восстановить уже удалённые дни, которых больше нет в исходном логе.

## Nightly

engine.nightly собирает доступные источники, затем crawl/load/signals/report.
Код 2: свежесть не пройдена; код 1: API не собран, но свежесть пока достаточна.
Даже при таком результате HTML и digest записаны. Секреты не печатаются;
ошибки API содержат только HTTP-код или безопасную категорию сетевой ошибки.
Никаких уведомлений, webhooks, установки launchd или изменений сайта.

## Round 2

source_status хранит прежние записи свежести; миграция сохраняет данные и rowid.
stat_registry пуст и зарезервирован для опубликованных чисел: id, name, value,
unit, sample_size, method, source, as_of, page, note.
Эксперименты импортируются из sites/<site>/import/effects.json, а не .ref.
Recon — только локальный импорт backfill 2026-11-10; его first samples явно
неполные. Последующий index evidence — свои wm_in_search_samples.json в raw.

Каждый API endpoint изолирован; {endpoint, error_class} без текста ошибки
сохраняется в *_manifest.json и collection.json. Пагинация сохраняет полученные
страницы даже при сбое следующей. Метрика продолжает после ошибки Вебмастера.
Команда collect --live возвращает 1 только после обработки всех источников.

Отчёт: totals и top 10 по score каждого правила, четыре статуса роботов по
семействам за 7 дней. Два последних окна GSC сравниваются по разделам и
страницам без суммирования окон; top 10 страниц по абсолютной разнице кликов,
затем показов. Отсутствующие строки помечены; это не доказанный ноль.
Если окно одно, это явно написано. Скользящие окна могут пересекаться.

Официальные дополнения к IP-снимку 2026-11-12 прочитаны 12.11.2026:
[Bing](https://www.bing.com/toolbox/bingbot.json),
[Claude](https://claude.com/crawling/bots.json),
[описание Anthropic](https://privacy.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).
Один общий список Claude применяется к ClaudeBot/Claude-User/Claude-SearchBot:
издатель подтверждает происхождение от Anthropic, класс запроса определяется UA.

## Proposals / weekly card (этап 3)

propose читает signal выбранной даты и пишет только proposal (payload JSON) и
локальный JSON. Повторный запуск заменяет черновики этой даты; id детерминирован.
Поля payload: kind, risk, pages, reach, potential, confidence, score, control,
control_note, reason (исходные numbers/source_rows), experiment и experiment_record.
Score = reach × potential × confidence. Reach — показы, запросы роботов или
показы страниц в последнем окне GSC (минимальный приоритет 1 при отсутствии).
Potential: metadata .25, links .20, остальные .15. Confidence: tech .80,
low_ctr/striking_distance .60, прочие .35. Это эвристики, не оценка эффекта.

Title/description и внутренние ссылки — low, переписывание/новая статья/обычная
техническая правка — medium, объединение/снятие/canonical/noindex/цены — high.
Движок не предлагает снять noindex автоматически: это только проверка с согласием.
Новая статья привязана к зрелой опорной странице с наблюдаемым спросом, а не к
придуманному URL. Возраст всех затрагиваемых страниц должен быть известен и
составлять >=28 дней на конец сигнального окна, не позже даты запуска.

experiment.record поддерживает JSON с treatment_pages/control_pages или
исторический текст с явными URL/путями. Все незакрытые статусы, включая unassessed,
резервируют опыт и контроль; явный список неактивных статусов и пример — в
ADD_A_SITE.md. Дополнительно учитываются page из change_log. Будущие опыты
исключены. Неявные группы в прозе не разворачиваются: нужен полный список URL.
Контроль — кандидат того же раздела (кластер предпочтителен), с близкими показами
и позицией в одном окне GSC; молодой, неизвестный или занятый опытами не подходит.
При отсутствии измерений/кандидата control=null: причинный вывод откладывается.

card фиксирует первый low/medium с максимальными очками в локальном файле
cards/<понедельник>.json; повторные даты недели не назначают вторую правку.
Если выбранная страница или контроль стали участником опыта, карточка отзывается
без замены. High публикуется только отдельным списком «Нужно согласие».
Карточка содержит гипотезу, метрику, окно до, порог +20% относительно контроля,
откат и плановую дату проверки +42 дня. Это черновик: реальную дату уточняют по
переиндексации и объёму данных. Движок не пишет experiment и не меняет сайт.
