# Контур

Переносимый SEO-движок: сбор → SQLite → сигналы → недельный HTML и текст.
Только Python 3.10+ и стандартная библиотека (`sqlite3` включён). Сайт не меняет,
письма и сообщения не отправляет, модели не вызывает. Supabase не используется.

```sh
# В этом checkout данные остаются внутри разрешённой папки.
export SEO_ENGINE_DATA="$PWD/.data/lida"
python3 -m engine.cli collect --site lida --date 2026-11-12 --backfill
python3 -m engine.cli crawl --site lida --date 2026-11-12
python3 -m engine.cli load --site lida --date 2026-11-12
python3 -m engine.cli signals --site lida --date 2026-11-12
python3 -m engine.cli report --site lida --date 2026-11-12
python3 -m unittest
```

Без `--live` collect читает только существующие выходные файлы; для API нужен
явный `--live`. `--start` и `--end` задают включительные границы окна API.
По умолчанию API-окно — 28 дней с задержкой 3 дня. Вебмастер дополнительно
запрашивает 60 дней истории индексации. Все ответы хранятся как получены.
Статистика окон не превращается в вымышленные дневные данные.

При устаревших или отсутствующих реальных данных `signals` сохраняет сигналы,
печатает `STALE` и завершает работу с кодом **2**. Это ожидаемо для текущих
данных Вебмастера и Wordstat. После него отдельно выполняется `report`.
`collect --live` возвращает **1** при недоступном сборщике, не пытается достать
ключ другим путём. Независимый сборщик и локальные источники обрабатываются.
`engine.nightly` выполняет все стадии, включая отчёт после ошибки свежести:

```sh
python3 -m engine.nightly --site lida --live
```

`sites/<name>/site.yaml` — JSON-совместимый YAML. Для другого сайта достаточно
одного такого конфига: домен, разделы, каталог файлов, начальный sitemap,
источники и имена Keychain. Все пути данных берутся из конфига, кроме
явного `SEO_ENGINE_DATA`. По умолчанию для Лиды — `~/seo-engine-data/lida/`.
Миниатюрный другой домен проходит весь CLI в `tests/test_engine.py`.

Живой GSC использует системные macOS `security` и `openssl`: RSA-ключ проходит
в OpenSSL через анонимный pipe, никогда не записывается в файл или лог.
Yandex OAuth-токен также читается только во время запуска из Keychain.
В других ОС офлайн-пайплайн работает без этих системных программ.

Данные: `<data>/raw/<date>/*.json`, `<data>/seo.sqlite`,
`<data>/signals/<date>.json`, `<data>/reports/<week-monday>.{html,txt,json}`.
Недельный файл обновляется последним запуском этой недели. Все сигналы остаются
в БД по датам; содержимое отчёта показывает окна каждого источника.
Не коммитьте raw и SQLite: они содержат закрытые данные аналитики.

Дневные роботы сохраняются без срока удаления; повторное чтение и ротация лога
не удваивают одинаковые запросы. IP берётся из настроенного доверенного proxy
заголовка, не из адреса туннеля. См. [контракты](docs/contracts.md).

IP-диапазоны обновляются отдельно: `python3 -m engine.cli ip-ranges --site lida`.
Сборка не доверяет названию UA и не переносит сегодняшнее доказательство IP
на прошлые даты. См. `playbooks/ip_sources.json` и датированные файлы.

Шаблон launchd [в репозитории](docs/ru.seo-engine.lida.nightly.plist): заменить
`__PYTHON3__`, `__REPOSITORY__`, `__DATA_DIRECTORY__`; **не установлен**.
Результаты реального прогона и ограничения — [REPORT.md](REPORT.md).
